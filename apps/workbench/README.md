# 镜流工坊 Web 工作台

基于 `design/workbench-v1/` 原型实现的 React + TypeScript 前端工程，使用 Vite 构建。与 Python 处理代码、原型文件和后续 Chrome 插件独立。

## 启动

需要 Node.js 22.13+（22.x）或 24+，推荐 Node.js 24 LTS。

在仓库根目录执行：

```bash
npm --prefix apps/workbench ci
npm --prefix apps/workbench run dev
```

打开 <http://127.0.0.1:5173>。开发服务只监听 `127.0.0.1`，端口占用会明确报错，不自动切换。

```bash
# 类型、规范、行为测试与生产构建
npm --prefix apps/workbench run typecheck
npm --prefix apps/workbench run lint
npm --prefix apps/workbench test
npm --prefix apps/workbench run build

# 本地预览构建产物
npm --prefix apps/workbench run preview
```

生产预览地址为 <http://127.0.0.1:4173>。使用 BrowserRouter，若以后部署到静态服务器，需要将页面路径回退到 `index.html`；资源文件仍按真实路径返回。

## 当前实现

| 路径        | 内容                                                        |
| ----------- | ----------------------------------------------------------- |
| `/`         | 动态任务统计、当前任务、需要关注、待发布成片、最近素材      |
| `/library`  | 名称搜索、类型筛选、网格/列表、多选、本地文件登记           |
| `/tasks`    | 状态筛选、任务搜索、批量创建、暂停/继续/重试、阶段与日志    |
| `/studio`   | 模板、素材池、种子、固定选片、逐镜头查看、输出选项          |
| `/publish`  | 产物区分、标题文案、封面策略、账号核对、预填/直接发布与回执 |
| `/settings` | 本地目录、转录模型、复用分析和保留长镜头偏好                |

新建任务、任务详情和素材详情使用原生 `<dialog>`，支持键盘焦点约束与 Esc 关闭。入口使用 URL 查询参数，因此可以直达详情；示例任务在刷新后不存在时，会显示内容未找到。

### 关键行为

- 统计从当前数据推导，创建任务、重试和发布回执会同步影响首页。
- 语义分镜自动补齐切镜、转录前置步骤，并固定处理顺序。
- 随机选片在相同素材、配置和种子下保持一致，创建混剪任务保存方案副本。
- 更改模板、素材池或种子后，需重新生成方案才能创建任务。
- 混剪演示完成后生成所选类型的产物记录，关联回原任务。
- 发布默认预填。切换产物、模式或编辑文案会取消已确认状态；直接发布还需二次确认。
- 剪映草稿不能直接发布。预览 MP4 会提示检查是否含最终标题和特效。
- 异步操作防止重复提交；加载失败、空列表和参数错误有对应状态。

## 数据边界

**当前尚未接入 Python API 或 Chrome 插件。** 页头始终显示“示例数据 · 服务未连接”，连接状态不会伪装为在线。

`DemoWorkspaceRepository` 提供内存示例数据：

- 不发送 HTTP 请求，不处理视频，不上传或发布，不读写真实配置。
- 选择文件只登记名称、大小和来源，不读取文件内容。
- 示例任务进度由详情中的“推进一个演示阶段”改变，不是实际处理进度。
- 本地选择的文件不会产生伪造的镜头、转录或预览；素材保持待处理状态。
- 发布记录和设置只在当前页面会话保留；刷新后恢复初始示例。
- 无凭据输入、无 Cookie 复制、无 localStorage 持久化。

素材沿用原型的信息视图，未嵌入占位图片。实际视频预览和缩略图待服务接入后实现。

## 代码结构与接入位置

```text
src/
├── app/                  应用入口、路由框架、状态提供器
├── components/           图标、按钮、弹窗、素材卡片、任务操作
├── data/                 示例数据与 WorkspaceRepository 实现
├── domain/               类型、参数校验、统计、固定选片逻辑
├── features/             文件登记、新建任务、详情抽屉
├── pages/                六个页面
├── main.tsx              React 入口与渲染错误边界
└── styles.css            设计变量、组件样式、响应式布局
```

`src/domain/types.ts` 定义的是前端领域模型与数据访问接口，**不是已经实现的 HTTP 协议**。后端接入时：

1. 从 Python OpenAPI/JSON Schema 生成传输类型，在独立 HTTP adapter 中转换为前端领域模型。
2. 替换 `src/app/App.tsx` 中的 `DemoWorkspaceRepository` 实例及模式标识。
3. 任务状态以服务返回值和 SSE 事件更新，去掉演示用“推进阶段”按钮。
4. 后端持久化素材 ID、任务、固定选片方案与发布回执；页面刷新后从服务恢复。
5. 发布由已配对扩展执行，保持目标账号检查、确认状态和预填/直接发布的区别。

示例混剪使用 42 秒/26 秒模板，只为落实当前 UI 设计，不代表 Python 多目录合成器的真实参数或算法。接入时以现有 CLI 的完整片段、目录顺序和 `--execute` 语义为准。
